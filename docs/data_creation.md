# PT Dataset Creation — Exact Definition

## Goal

Create training data that teaches model **G** to skip unnecessary steps in **its own reasoning**.

The training example is always:

```text
question + accepted useful reasoning prefix -> next useful step generated by G
```

This is **not** summarization and **not** editing a completed trace.

---

## Models

* **G**: the model being improved. It generates every reasoning trace used in the dataset.
* **D**: a decision model. It only selects a safely removable span inside G's generated reasoning.

Critical rule:

```text
target_y must come from G's output, never from D.
```

---

## Exact Data Creation Algorithm

For each source question `q`:

```text
context = q
depth = 0
```

Repeat:

1. Generate a new reasoning continuation:

```text
trace = G(context)
```

2. Split `trace` into ordered reasoning units:

```text
[u0, u1, ..., un]
```

3. Ask `D` to find the first safely removable contiguous span:

```text
[ui, ..., uj]
```

A valid removable span must have a next unit:

```text
j < n
```

4. Create one training row:

```text
useful_prefix = [u0, ..., u(i-1)]
removed_span  = [ui, ..., uj]
target_y      = u(j+1)

input_x = context + useful_prefix
```

5. Save the row.

6. Create the next context:

```text
context = input_x + target_y
depth = depth + 1
```

7. Run `G(context)` again to generate a **new continuation**.

Stop when D finds no safe removable span or the configured depth limit is reached.

---

## Critical Depth Rule

Depth does **not** mean repeatedly deleting sentences from one fixed original trace.

Depth means:

```text
depth 0: generate from the original question
depth 1: generate again from the context after the first skip
depth 2: generate again from the context after the second skip
```

At every depth, G generates a fresh continuation from the already-pruned context.

---

## Example

Question:

```text
If a train travels 60 km in 1 hour, how far does it travel in 90 minutes?
```

### Depth 0

G generates:

```text
A: The train's speed is 60 km/h.
B: Now I need to convert the time.
C: 90 minutes is 1.5 hours.
D: Distance = 60 × 1.5 = 90 km.
```

D removes `B`.

Save:

```text
input_x:
Question + A

target_y:
C

pruning_depth:
0
```

Next context:

```text
Question + A + C
```

### Depth 1

G generates a new continuation from `Question + A + C`:

```text
E: I can now calculate the distance.
F: Distance = 60 × 1.5 = 90 km.
```

D removes `E`.

Save:

```text
input_x:
Question + A + C

target_y:
F

pruning_depth:
1
```

## Canonical Row Format

```json
{
  "id": "...",
  "question": "...",
  "context_before_generation": "...",
  "generated_trace": "...",
  "generated_units": ["..."],
  "input_x": "...",
  "target_y": "...",
  "pruning_depth": 0,
  "metadata": {
    "generator_model": "...",
    "generator_model_revision": "...",
    "decision_model": "...",
    "removed_span": ["..."],
    "removed_start_index": 0,
    "removed_end_index": 0,
    "decision_reason": "..."
  }
}
```

## Dataset Output

Save the result as a versioned Hugging Face Dataset with two views:

```text
canonical:
    Full rows with traces, decisions, depth, and metadata.

training:
    prompt = input_x
    completion = target_y
```

---

## Invalid Implementations

These are wrong:

* Hand-written reasoning traces used as the real dataset.
* Manual `removable_index` used as the real pruning process.
* D writing or rewriting `target_y`.
* Training on `full trace -> shortened trace`.
* Creating deeper depths by deleting more steps from the same frozen trace.

The real pipeline is:

```text
G generates -> D selects a skip -> save transition row
-> build pruned context -> G generates again -> repeat
```
